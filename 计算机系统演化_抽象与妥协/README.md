# 《计算机系统演化：抽象与妥协》课程总纲

* **课程定位**：计算机系统与现代 AI 基础设施进阶课
* **前置要求**：掌握基础编程（C / Python），学完 `Nand2Tetris`（前半部硬件构造）与 `OSTEP`（虚拟内存与并发基础）核心章节
* **学时配置**：**48\~64 学时（32 学时理论推演 + 16\~32 学时沙盒实验）**

## 一、 课程定位与设计理念

这门课用来衔接经典单机系统教材（`Nand2Tetris`、`OSTEP`、`计算机网络`）与现代深度学习（`D2L`）。

课程重点探讨**传统 CPU/操作系统机制、现代 GPU 并行架构，以及大模型推理与训练系统之间的内在联系**。通过“理论推演 + 沙盒实验”的配合，帮助学习者在受限的硬件条件下建立起清晰的工程权衡直觉。

### 三个核心设计原则

1. **经典系统与现代 AI 系统的对照学习**
   每个模块持续两周：奇数周拆解底层硬件与操作系统的核心设计（例如 **CPU 的乱序流水线 vs. GPU 的大规模并行锁步执行**、**操作系统的线程切换开销 vs. GPU 靠大容量寄存器实现的零开销线程切换**）；偶数周对应到现代大模型系统（FP8 量化、投机采样、vLLM 的 PagedAttention、Continuous Batching、多卡并行策略、Triton 算子分块融合），看清不同年代的系统工程师是如何面对同类物理瓶颈的。
2. **用定量公式做性能分析**
   全课程使用三个基础定量工具来分析系统瓶颈：
   * **Roofline 模型（屋顶线模型）**：根据算术强度（每搬运 1 字节数据能做多少次浮点运算，即 $\text{FLOPs}/\text{Byte}$），判断程序当前是受限于**计算能力（Compute-Bound）**还是受限于**内存带宽（Memory-Bound）**。
   * **阿姆达尔定律（Amdahl's Law）与利特尔法则（Little's Law, $L = \lambda W$）**：用来计算多卡并行时的通信等待占比、高并发下的排队延迟，以及掩盖显存延迟所需的并发线程数。
3. **直接写核心机制的沙盒实验**
   实验环境已经封装好了硬件模拟器和测试负载，省去配环境和写外围样板代码的时间。学习者只需在沙盒里编写 100\~200 行核心代码——比如**低精度块级量化、页表映射与写时复制、连续批处理调度器、多卡通信重叠、以及基于片上缓存分块（Tiling）的矩阵乘法**，由模拟器直接测出运行周期、缓存命中率和综合得分。

## 二、 16 周排课总表

| 周次 | 模块核心议题 | 理论推演 (每周 2\~2.5 学时) | 沙盒实验 (每两周 2\~3 学时) |
| :---: | :--- | :--- | :--- |
| **01** | **导论：系统的第一性原理** | 抽象的本质（有损压缩）、三大物理限制（芯片面积、功耗、光速延迟），以及 Roofline 模型与利特尔法则。 | *(熟悉硬件模拟器与基准性能测试)* |
| **02** | **数值表示：连续与离散** | 从 IEEE 754 浮点数标准，到大模型的 BF16 / FP8 / INT4 分块量化技术。 | **沙盒 1：精度与面积权衡。** 编写分块量化与随机舍入代码，在有限的芯片面积预算下控制精度损失并防止数值溢出。 |
| **03** | **执行模式：CPU 乱序 vs GPU 并行** | 追求低延迟的 CPU（分支预测与乱序执行）vs. 追求高吞吐的 GPU（SIMT 线程束锁步执行与分支分化问题）。 | *(无实验)* |
| **04** | **跨代对照：硬件投机到 AI 推理** | 从 CPU 投机执行与幽灵（Spectre）漏洞，到大模型推理的投机采样（Speculative Decoding）。 | **沙盒 2：消除分支分化与投机解码。** 上半场改写存在严重分支分化的 GPU 代码；下半场实现小模型草稿猜词与大模型并行验证。 |
| **05** | **内存空间：局部性与碎片问题** | 存储金字塔的速度与容量矛盾，缓存冲突，以及连续内存分配带来的外部碎片问题。 | *(无实验)* |
| **06** | **跨代对照：虚拟分页到显存管理** | 操作系统的页表、快表（TLB）与写时复制（CoW），对比 vLLM 的 PagedAttention 显存管理。 | **沙盒 3：实现分页管理与前缀缓存。** 编写固定块映射表、写时复制与前缀复用逻辑，解决 KV Cache 的显存碎片问题。 |
| **07** | **时间调度：抢占切换 vs 延迟掩盖** | CPU 线程切换的高昂代价 vs. GPU 依靠超大寄存器堆实现的零开销线程切换（Occupancy 延迟掩盖）。 | *(无实验)* |
| **08** | **跨代对照：异步事件到连续批处理** | 从操作系统的 `epoll` 异步机制与排队延迟，到推理引擎的 Continuous Batching 与分块预填充（Chunked Prefill）。 | **沙盒 4：编写推理调度器。** 实现按单步迭代动态插拔请求与分块预填充逻辑，在长短请求混合时兼顾首字延迟与吞吐量。 |
| **09** | **跨节点通信：延迟限制与分布式共识** | 带宽延迟积、TCP 拥塞控制原理（BBR），以及 CAP 定理与 Raft 共识算法的核心安全规则。 | *(无实验)* |
| **10** | **跨代对照：多卡并行与 RDMA 网络** | 大模型三种并行策略（数据并行 DP/ZeRO、张量并行 TP、流水线并行 PP）的通信开销，以及 RDMA 零拷贝技术。 | **沙盒 5：多卡切分与通信重叠。** 在多机多卡模拟器中配置并行切分方案，并让反向传播计算与梯度通信重叠执行。 |
| **11** | **编程抽象：高级语言与硬件的脱节** | 为什么传统 C 语言平坦内存和单线程的假设，难以直接发挥现代多核与 GPU 硬件的性能？ | *(无实验)* |
| **12** | **跨代对照：片上缓存分块与 Triton** | 矩阵乘法的片上 SRAM 分块（Tiling）、双缓冲预取、FlashAttention 在线计算，以及 Triton 的块级编程思想。 | **沙盒 6：矩阵分块与算子融合。** 编写块级矩阵乘法与 FlashAttention 代码，通过缓存复用把硬件算力利用率从个位数提升到 85% 以上。 |
| **13** | **计算范式：确定性极限与概率近似** | 图灵机停机问题与组合爆炸瓶颈，如何用布隆过滤器、近似检索等概率方法换取时间和空间。 | *(无实验)* |
| **14** | **前沿探讨：概率大模型与确定性护栏** | 把大模型看作“概率处理器”，利用状态机约束解码（FSM Mask）和沙箱测试构建可靠的 Agent 系统。 | **沙盒 7：状态机约束解码与重试闭环。** 实现基于语法状态机的输出限制器与按需多路采样，把多步工具调用的成功率提升到 98%。 |
| **15** | **工程设计复盘** | 为什么“更坏即更好（Worse is Better）”和“苦涩的教训（The Bitter Lesson）”反复在计算机历史中应验？ | *(无实验)* |
| **16** | **期末综合系统设计挑战** | *(理论停课)* | **沙盒 8：受限硬件下的全栈整合。** 在严格受限的缓存、显存、带宽和功耗预算下，组合所学技术跑通混合推理负载。 |

## 三、 考核与评分标准

课程通过三个维度进行客观评分，重点考察对底层机制的实现能力与资源统筹能力：

### 1. 日常沙盒实验与帕累托边界评分 (40%)

每次实验提交核心机制代码，由模拟器自动运行测试负载并按量化指标打分：

* **及格线（基础分 60%）**：功能正确，在并发压力与边界数据下不出现死锁、内存溢出（OOM）、数值溢出（`NaN`）或结果错误。
* **优秀线（权衡分 85%）**：同时考核两组相互制约的指标（例如 **高吞吐量 vs. 低尾延迟**，或 **大计算分块 vs. 硬件活跃线程占用率**）。代码的性能表现需要达到预设的帕累托最优区间。
* **极客榜（满分 100%）**：公开实时排行榜。在极为有限的硬件预算下（例如缩减一半的片上缓存与受限带宽），看谁的方案能跑出最高的有效吞吐量。

### 2. 阶段作业：全链路性能拆解与故障复盘 (30%)

每两个模块（第 4、8、12、15 周）结束后，提交一份技术分析报告（共 4 份）：

* **全链路开销拆解**：完整计算一个请求从进入系统到返回结果的每一步耗时与资源占用。例如追踪一个 Token 在推理引擎中经历的分词、页表查找、片上缓存搬运、多卡同步与网络传输，算出每一步分别消耗了多少微秒和多少带宽。
* **真实故障复盘**：针对历史上真实的系统故障或漏洞（如 CPU 幽灵漏洞、分布式集群因慢节点引发的通信卡死、网络拥塞风暴），分析当时哪一层的抽象假设失效了，并给出改进方案。

### 3. 期末考核：受限条件下的架构决策题 (30%)

采用开卷设计题。给出变化的硬件参数与业务要求，考察学习者能否用 **Roofline 模型、内存与并发公式** 算清账目，做出合理的取舍，并针对副作用设计补救措施。

#### 典型考题示例

> **背景**：你正在负责研发一款边缘端大模型推理引擎。硬件团队通知你：下一代芯片为了放入更多低精度计算单元（峰值算力翻倍），将每个核心的**片上缓存（SRAM）与寄存器堆容量缩减了 30%**，但通过升级封装使**外部内存带宽翻了一倍**。
>
> 面对严格的延迟指标，你有三个方向的方案可以选择：
> * **方案 A（降低数值精度）**：全面改用 INT4 分块量化，接受复杂逻辑推理任务上的一定精度下降。
> * **方案 B（打破串行解码）**：引入投机采样（Speculative Decoding），利用翻倍的内存带宽和算力，先用小模型猜词再用大模型并行验证。
> * **方案 C（调整分块与显存管理）**：缩小算子融合的分块（Tile）尺寸以减少单个线程的寄存器占用，维持足够的硬件并发线程数（Occupancy），并配合细粒度的分页显存调度。
>
> **要求**：
> 1. **定量分析硬件变化的影响**：在 Roofline 图中画出硬件调整前后的变化。分析为什么“峰值算力翻倍、外部带宽翻倍，但片上缓存与寄存器减少 30%”会让原本使用大分块（Large Tile）的算子因为**寄存器溢出（Register Spilling）和并发度下降**而性能大跌？
> 2. **给出决策路径**：你会优先选择哪两个方案配合使用？为什么在外部内存带宽已经翻倍的情况下，单纯靠方案 A 压低精度带来的收益不如从前明显？
> 3. **设计补救措施**：你选择的方案会带来什么新的副作用（例如缩小分块导致外部内存读写次数增加，或投机采样在高随机性任务下命中率降低）？请给出对应的动态调整方案。
